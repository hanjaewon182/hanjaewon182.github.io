왜 만들었나

학교 공지는 여러 게시판에 흩어져 있고 하루에도 많이 올라와서, 나에게 해당하는 공지와 마감을 놓치기 쉽습니다. 공지를 한곳에 모으고, 나와 관련된 것만 마감 순으로 먼저 보여 주는 것을 목표로 했습니다.

동작 흐름

학교·학과 게시판 + 온통청년 수집→Gemini로 대상·마감·할 일 추출→내 설정과 비교해 별점 0~3→디스코드 아침 브리핑 + 웹페이지

주요 기능

공지 자동 수집

학교 일반·학사·장학 게시판과 내 학과 게시판, 온통청년 청년정책을 모아 옵니다.

AI 정보 추출

공지 본문(이미지 공지 포함)에서 대상, 마감일, 할 일, 준비물을 뽑아 정리합니다.

나에게 맞는 순 정렬

학과·학년·학적·생활관·나이·지역 설정과 비교해 ★0~3 별점과 판단 이유를 붙입니다.

아침 브리핑

날씨, 마감 임박, 새 공지를 디스코드로 매일 보내고 전체 목록은 웹페이지에서 봅니다.

코드 없이 설정 변경

GitHub 이슈 양식으로 내 정보를 바꾸면 별점이 자동으로 다시 계산됩니다.

누구나 복사해서 사용

저장소를 복사하고 키만 넣으면 자기 학과·지역으로 바로 쓸 수 있습니다.

내가 맡은 일

  • AI 정보 추출Gemini로 공지에서 대상(학과·학년·학적·생활관), 마감일, 할 일, 준비물을 JSON으로 추출. 이미지로만 된 공지도 읽도록 구현
  • 자동 실행 설계수집 → AI 정리 → 날씨 → 별점 → 알림이 하루 4번 돌아가는 GitHub Actions 워크플로 설계, 단계별 시간 제한과 실패 처리
  • 설정 기능GitHub 이슈 양식으로 학과·학년·관심 분야·나이·지역을 바꾸면 별점이 다시 계산되는 기능
  • 청년정책 연결온통청년 API를 직접 조사해 데이터 형식 문서를 만들어 팀에 공유하고, 설정에 나이·지역 추가
  • 날씨기상청 단기예보 API로 학교 위치의 기온·강수확률 제공
  • 팀장역할·일정 관리, 팀원 PR을 실제 데이터로 돌려 본 뒤 리뷰·머지 (전체 27건 중 22건)

배운 점

처음에는 기능을 만들기만 하면 끝이라고 생각했는데, 매일 실제로 돌아가게 하는 것이 훨씬 어렵다는 걸 알게 됐습니다. 테스트 데이터로는 보이지 않던 문제가 실제 공지를 돌리자 하나씩 드러났고, 이를 고치며 "돌아간다"와 "믿고 쓸 수 있다"는 다르다는 걸 배웠습니다. 팀장으로서 각자 만든 코드를 합칠 때 데이터 형식부터 맞추는 것이 중요하다는 것도 경험했고, 그래서 청년정책을 붙일 때는 API를 먼저 확인하고 형식 문서부터 만들어 공유했습니다.
